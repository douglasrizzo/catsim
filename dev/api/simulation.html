Simulation Runs and Results#

catsim.simulate(engine: CatEngine, *, true_thetas: npt.ArrayLike | None = None, responses: npt.ArrayLike | None = None, rng: int | numpy.random.Generator | None = None, parts: int = 1, workers: int = 1, progress: Callable[[int, int], object] | None = None) → SimulationResult[source]#

Run one CAT session per examinee on an engine, in parts that can run on several processes.

Each examinee has an answer to every item of the bank, possibly missing for a recorded examinee, and its session takes the answer to each item it is given from them (ADR-0014). The examinees are given in one of three ways:

  • true_thetas alone: generated examinees. Before its test, examinee i draws one uniform number \(u_j\) per item of the bank, and its answer to item \(j\) is correct when \(u_j < P_j(\theta_i)\), the item’s probability of a correct answer at the true ability \(\theta_i\) (true_thetas[i]).

  • responses alone: recorded examinees, whose true abilities are unknown. Row i holds examinee i’s answers. The items whose answer is missing are excluded from the start of the session (ADR-0011), so a recorded examinee is given only items they answered, and one who runs out of them ends with StopReason.NO_ITEMS.

  • Both: recorded examinees whose true abilities are known, as when a study draws its own response matrix with a response model of its choice.

Every random draw comes from rng (ADR-0013). The run takes one root entropy from it, and examinee i, at position i of the run, draws from two streams of its own: SeedSequence(entropy, spawn_key=(i, 0)) for its answers to every item, and SeedSequence(entropy, spawn_key=(i, 1)) for its session, the generator of its start, select and answer steps, from which the initializer, the selector and the exposure control draw. A generated examinee therefore gives the same answer to an item whatever the engine and whenever the item comes, so two engines run on the same seed and examinees are compared on common random numbers.

The examinees are split, in order, into parts contiguous parts of near-equal size, and each part runs its sessions one after another (ADR-0015). Each session’s selections are capped against the items’ exposure rates: each item’s administrations over the sessions before it in its part (ADR-0012), so the first session of a part sees no rates. This exposure feedback is the only way one session depends on another, and the parts are part of the run’s configuration: with an r_max cap, a session sees only the exposure of its own part, so parts changes the result, and parts=1, the default, is the sequential run. Without a cap, an examinee’s session depends on neither the other examinees nor parts.

The parts run on up to workers processes, which never change the result: it depends only on the engine, the examinees, the seed and parts. With more than one part and more than one worker, the parts run on processes of Python’s standard library, spawned on every platform. Each receives the engine pickled and imports every class and function it refers to by its module and name, so a strategy defined in a notebook or a script’s main module, a lambda (such as a custom log_prior) or a function defined inside another function raises before any part runs: define it in a module and import it from there. A script that runs on workers calls simulate under if __name__ == "__main__":, as every process pool of Python requires.

The Running Simulations guide runs a study and reads its result.

Parameters:
engineCatEngine

The engine whose item bank and strategies every session uses.

true_thetasarray-like or None, optional

The examinees’ true abilities: a non-empty, one-dimensional sequence of finite numbers. To simulate n examinees from a population, draw their abilities, e.g. numpy.random.default_rng(1).normal(0, 1, n). Default is None, for recorded examinees whose abilities are unknown.

responsesarray-like or None, optional

The recorded examinees’ answers: a matrix with one row per examinee and one column per item of the bank, of Booleans, of the integers 0 and 1, or of the floats 0.0 and 1.0 with NaN where an answer is missing. Default is None, for generated examinees.

rngint, numpy.random.Generator or None, optional

The source of the run’s root entropy. None, the default, takes fresh entropy, so every call gives other tests. A non-negative int is the entropy itself, so the same seed gives the same result. From a generator, one 128-bit number is drawn as the entropy, which advances it, so passing the same generator to another run gives other results; a call whose inputs fail their checks draws nothing from it.

partsint, optional

The number of parts the examinees are split into, from 1 to the number of examinees: each part holds the next examinees in order, and the first n % parts of the parts of n examinees have one examinee more than the others, the sizes of numpy.array_split. Default is 1, the sequential run.

workersint, optional

The most processes the parts run on at once, a positive integer. With 1, the default, or with one part, the calling process runs the parts itself, one after another; otherwise min(workers, parts) worker processes run them.

progresscallable or None, optional

Called in the calling process as progress(finished, total) after each session ends, with the number of sessions finished and the number of examinees, such as lambda finished, total: bar.update(1) for a progress bar bar. On workers, the sessions end in the order the processes run them, and each call still counts one more session. Default is None.

Returns:
SimulationResult

The sessions, in examinee order, with the true abilities (None for recorded examinees whose abilities are unknown), the run’s exposure and proposal counts, summed over its parts, the number of parts, and the run’s duration: the wall-clock time in the calling process from the start of the first part to the end of the last. On workers it includes starting them and sending them the engine, so it depends on workers and on the machine, which the sessions do not.

Raises:
TypeError

If engine is not a CatEngine; neither true_thetas nor responses is given; true_thetas is a single number, holds values that are not real numbers or has more than one dimension; responses is not two-dimensional or holds values that are neither Booleans nor real numbers; rng is neither None, an integer nor a generator; parts or workers is not an integer; or progress is neither None nor callable.

ValueError

If true_thetas or responses is empty; a true ability is not finite; responses does not have one column per item of the bank, or holds a response other than 0, 1 and NaN; the two inputs have different numbers of examinees; rng is a negative integer; parts or workers is less than 1; parts exceeds the number of examinees; or, when the parts run on workers, the engine refers to a class or function the workers cannot import, or cannot be pickled.

Examples

Generated examinees, drawn from a standard normal population:

>>> import numpy
>>> from catsim import CatEngine, simulate
>>> from irtlib import ItemBank
>>> from catsim.estimation import EAPEstimator
>>> from catsim.initialization import FixedPointInitializer
>>> from catsim.selection import MaxInfoSelector
>>> from catsim.stopping import MaxLengthStopper
>>> bank = ItemBank.generate(50, rng=0)
>>> engine = CatEngine(bank, FixedPointInitializer(0.0), MaxInfoSelector(), EAPEstimator(), MaxLengthStopper(10))
>>> thetas = numpy.random.default_rng(1).normal(0, 1, 100)
>>> result = simulate(engine, true_thetas=thetas, rng=0)
>>> len(result.sessions), result.examinees()["test_length"].tolist() == [10] * 100
(100, True)

Without an exposure cap, the run’s four parts give the sequential run’s sessions, and two workers give the same sessions as one:

>>> in_parts = simulate(engine, true_thetas=thetas, rng=0, parts=4, workers=2)
>>> in_parts.parts, in_parts.sessions == result.sessions
(4, True)

Two recorded examinees: the first answered every item correctly, the second only items 3, 8 and 15, so the second runs out of answered items after three:

>>> responses = numpy.full((2, bank.n_items), numpy.nan)
>>> responses[0] = 1.0
>>> responses[1, [3, 8, 15]] = [1.0, 0.0, 1.0]
>>> result = simulate(engine, responses=responses, rng=0)
>>> [(len(session.administered_items), str(session.stop_reason)) for session in result.sessions]
[(10, 'stopper'), (3, 'no_items')]
>>> sorted(result.sessions[1].administered_items)
[3, 8, 15]
>>> result.rmse()

class catsim.SimulationResult(*, item_bank: ItemBank, sessions: tuple[Session, ...], proposal_counts: IntArray, duration: float, true_thetas: FloatArray | None = None, parts: int = 1)[source]#

The sessions of a simulated run, with the run’s tables and metrics (ADR-0016).

simulate() returns one; one can also be built from sessions an application ran itself, whose true abilities may be unknown. A result is immutable: its sessions are a tuple of Session values, which never change, and its arrays are read-only. It compares by identity.

Tables. steps() has one row per session and step, examinees() one row per session, deciles() one row per decile of the true ability and ability_levels() one row per distinct true ability. Each is a dict of equal-length NumPy columns, which pandas.DataFrame(result.steps()) and polars take as they are, and which csv.DictWriter writes row by row. Items appear by index and by name (ADR-0004).

Metrics. bias(), mse(), rmse(), test_length(), se(), exposure_rates() and overlap_rate() each return a Metric, the value and its Monte Carlo standard error, computed by catsim.metrics over the run’s sessions, or with decile=k over the sessions of decile k only; proposal_rates() covers the whole run. The Monte Carlo errors treat the sessions as independent: with exposure feedback (an r_max cap), each session depends on the sessions before it, so the errors are approximations, and replications of the run give the exact spread. A decile with no session gives NaN. Bias, MSE and RMSE, and every metric by decile, need the true abilities, and raise without them.

Deciles. Decile \(k\), from 0 to 9, holds the sessions whose true ability \(\theta\) has \(q_k \leq \theta < q_{k+1}\), where \(q_0, \ldots, q_{10}\) are the quantiles of the run’s true abilities at \(0, 0.1, \ldots, 1\), interpolated linearly (NumPy’s default, R’s type 7), and decile 9 also holds the abilities equal to \(q_{10}\), the highest. With \(N\) distinct abilities, each decile holds \(N/10\) sessions when 10 divides \(N\). Equal abilities always share a decile, so with ties some deciles may hold more sessions and others none: when every examinee has the same ability, all are in decile 9.

The Running Simulations guide reads a result.

Parameters:
item_bankItemBank

The item bank the sessions drew from.

sessionsSequence[Session]

The run’s sessions, at least one, in examinee order, each ended. Stored as a tuple.

proposal_countsarray-like

Each item’s proposals over the run, as integers: its administrations plus the times the engine’s exposure control declined it. A session proposes an item at most once, so a count is between the item’s administrations and the number of sessions. Without an exposure control, the proposals are the administrations.

durationfloat

The run’s wall-clock time, in seconds.

true_thetasarray-like or None, optional

Each session’s true ability, a finite number, in session order, or None when the true abilities are unknown, as for recorded examinees. A session does not hold its examinee’s true ability, so the result does. Default is None.

partsint, optional

The number of contiguous parts the run’s examinees were split into, each with exposure counts of its own (ADR-0015). Default is 1, a sequential run.

Attributes:
exposure_countsnumpy.ndarray

Each item’s administrations over the run, counted from the sessions.

Raises:
TypeError

If item_bank is not an irtlib.ItemBank, duration is not a number, a session is not a Session, the proposal counts are not integers, or parts is not an integer.

ValueError

If duration is negative or not finite, there is no session, a session has not ended or administered an index the bank does not have, true_thetas does not hold one finite number per session, the proposal counts are not one per item between its administrations and the number of sessions, or parts is not positive.

Examples

>>> import numpy
>>> from catsim import CatEngine, simulate
>>> from irtlib import ItemBank
>>> from catsim.estimation import EAPEstimator
>>> from catsim.initialization import FixedPointInitializer
>>> from catsim.selection import MaxInfoSelector
>>> from catsim.stopping import MaxLengthStopper, StandardErrorStopper, StopRule
>>> engine = CatEngine(
...   ItemBank.generate(100, rng=0),
...   FixedPointInitializer(0.0),
...   MaxInfoSelector(),
...   EAPEstimator(),
...   StopRule(StandardErrorStopper(0.5), MaxLengthStopper(30)),
... )
>>> result = simulate(engine, true_thetas=numpy.random.default_rng(1).normal(0, 1, 200), rng=0)
>>> value, mc_se = result.rmse()
>>> print(f"RMSE {value:.3f} ± {mc_se:.3f}, mean length {result.test_length().value:.1f}")
RMSE 0.472 ± 0.025, mean length 13.9
>>> list(result.steps())
['session', 'position', 'item', 'name', 'response', 'theta', 'se', 'evaluations', 'true_theta']
>>> by_decile = result.deciles()
>>> by_decile["n_sessions"].tolist()
[20, 20, 20, 20, 20, 20, 20, 20, 20, 20]
>>> by_decile["test_length"].round(1).tolist()
[14.8, 13.4, 13.3, 14.0, 13.2, 13.2, 14.2, 14.1, 14.4, 14.8]

The tests differ in length, so there is no overlap rate:

>>> result.overlap_rate() is None
True
ability_levels() → dict[str, ndarray][source]#

Return the table of the run’s metrics at each distinct true ability: one row per ability, from the lowest.

It suits designs that give many examinees each of a few true abilities, such as 100 at each of 13 abilities from -3 to 3, which deciles() would group unevenly: 13 abilities do not fit in 10 deciles. Equal abilities are those that compare equal.

Returns:
dict[str, numpy.ndarray]

One row per distinct true ability, with the columns of deciles() but decile: n_sessions, true_theta (the ability itself), and the metrics and their Monte Carlo errors. An ability held by a single session has NaN Monte Carlo errors.

Raises:
ValueError

If the result has no true abilities.

deciles() → dict[str, ndarray][source]#

Return the table of the run’s metrics by decile of the true ability: one row per decile, from the lowest.

Returns:
dict[str, numpy.ndarray]

Ten rows, with the columns:

  • decile (int): 0 to 9;

  • n_sessions (int): how many sessions the decile holds;

  • true_theta (float): the mean true ability of its sessions;

  • bias, mse, rmse, test_length, se and overlap_rate (float): the metrics of the methods of those names with decile set, each followed by its Monte Carlo error, bias_mc_se to overlap_rate_mc_se. The overlap rate is NaN for a decile whose tests differ in length.

A decile with no session has NaN for every float.

Raises:
ValueError

If the result has no true abilities.

examinees() → dict[str, ndarray][source]#

dict[str, numpy.ndarray]

The columns, each with one entry per session:

steps() → dict[str, ndarray][source]#

Return the table of the run’s steps: one row per session and administered item.

The rows are in session order, and in the order the items were given within a session.

Returns:
dict[str, numpy.ndarray]

The columns, each with one entry per row:

  • session (int): the session’s position in the run, its examinee’s position;

  • position (int): the item’s position in its session’s test, 0 for the first, so the row’s item is sessions[session].administered_items[position];

  • item (int): the item’s index in the bank;

  • name (str): the item’s name, item_bank.names[item];

  • response (bool): the examinee’s response;

  • theta (float): the ability estimate after the response;

  • se (float): its standard error;

  • evaluations (float): how many times the estimator evaluated its objective for that estimate, NaN where the estimator gave no count (Estimate);

  • true_theta (float): the examinee’s true ability, a column only when the result has true abilities.

Each session’s initial estimate, which precedes its first item, is the first of the session’s estimates.
